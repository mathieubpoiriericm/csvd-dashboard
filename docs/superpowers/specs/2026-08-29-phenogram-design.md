# Phenogram Karyogram — Design Spec

Date: 2026-08-29 Status: draft for review. Sibling of
`docs/superpowers/specs/2026-08-29-timeline-radar-design.md`; follows the same
two-renderer contract.

## Context

`static/phenogram.html` is not an SVG. It draws a 362 KB WebP raster
(`static/images/phenogram.webp`, 7800×4800, a Ritchie Lab PhenoGram output
carried over from the Shiny app) onto a `<canvas>` and answers hover by sampling
the pixel under the cursor and nearest-matching it against a 15-entry colour
table (`phenogram.html:246-310`, `:381-398`). The tooltip names the phenotype,
never the gene. No generator exists in this repo or its history; the wrappers
only harden the artifact.

Defects in the artifact and its wrapper:

- **Out of sync with `data/table1.json`.** ABO (`9q34.2`) is labelled "APOE";
  C6orf195 (`6p25.2`) and COL4A1/2 (`13q34`) are missing, so chromosome 13 is
  never drawn. 61 labels for 63 genes.
- Pointer-only, no keyboard path, no link to the gene table or NCBI.
- The trait vocabulary is duplicated with casing that already differs from
  `lib/constants.ts:62-79` (`extreme-cSVD` vs `Extreme-cSVD`); nothing ties it
  to the data.
- Needs `allow-scripts allow-same-origin` — the app's only such sandbox — or the
  canvas is tainted (`routes/phenogram.tsx:9-27`).
- Pure yellow, cyan and magenta markers on a white plate (HIP-PVS, MD,
  Extreme-cSVD, WM-PVS) have no contrast; 14 unrelated hues carry identity with
  colour alone, which fails colour-blind readers and every printed copy.

Spike (2026-08-29, plan file): as of today no Python package produces an
interactive, accessible karyogram — 2025–2026 added four _static_ matplotlib
ideogram packages, none with labelled markers — and ideogram.js (the only JS
contender) has had no commit since 2025-05-20, weighs 112 KB gz, and has no
keyboard or ARIA story. Decision: **draw the figure in-app** from the committed
data and keep a **reproducible matplotlib drawing** for the manuscript.

## Design: two renderers, one contract

```text
data/table1.json ─────────────┬──> lib/phenogram.ts ──> islands/Phenogram.tsx (SVG figure + HTML gene buttons)
data/cytobands_hg38.json ─────┤          ▲
lib/phenogram_encoding.json ──┤  (families, colours, labels, definitions, stains, layout constants)
                              └──> scripts/phenogram_figure.py ──> figures/phenogram.{svg,pdf,png} (matplotlib)
```

Same rule as the timeline: **encoding shared, computation duplicated on
purpose.** Everything that could drift — colours, order, labels, definitions,
geometry constants — lives in one committed JSON read by both renderers; the
~40-line layout rule (place by band, stack label blocks, resolve collisions) is
written once per language so the paper script runs from the data alone.

### Cytoband table — `data/cytobands_hg38.json`

Generated by `scripts/fetch_cytobands.py` (stdlib only: `urllib`, `gzip`,
`json`) from UCSC `hg38/database/cytoBandIdeo.txt.gz`, filtered to chr1–22, X, Y
in `CHROMOSOMES` order (`lib/sorting.ts`), committed like every other
`data/*.json` (862 bands, ~6 KB gz). `deno task cytobands` →
`uv run scripts/fetch_cytobands.py`.

```json
{
  "assembly": "hg38",
  "source": "https://hgdownload.soe.ucsc.edu/goldenPath/hg38/database/cytoBandIdeo.txt.gz",
  "chromosomes": [
    {
      "name": "1",
      "length": 248956422,
      "bands": [
        { "name": "p36.33", "start": 0, "end": 2300000, "stain": "gneg" }
      ]
    }
  ]
}
```

**Placement rule.** `placeGene(location)` parses
`^(\d{1,2}|X|Y)([pq]\d+(?:\.\d+)?)$`, requires an exact band-name match on that
chromosome, and returns the band midpoint. Anything else is `unplaced` — never a
prefix guess, so a bad string cannot land silently on the wrong band. Verified
2026-08-29: all 49 distinct `chromosomalLocation` values in the committed table
are exact hg38 band names, so **no pipeline change is needed**. Base-pair
precision later is one line away (`pipeline/ncbi_gene_fetch.py:186-188` already
receives NCBI esummary `maplocation`/`genomicinfo` and discards them) —
deferred.

- `traits[].key` is the raw data value (`"extreme-cSVD"`, `"lacunes"`,
  `"stroke"`, `"lacunar stroke"`); `label` is the display form. The 14 traits
  map onto **7 families**: PVS (BG-PVS, WM-PVS, HIP-PVS), Diffusion MRI (PSMD,
  FA, MD, NODDI), Extreme cSVD, WMH, Stroke (SVS, stroke, lacunar stroke), CMB,
  Lacunes. `(none found)` is the sentinel from `lib/constants.ts`, not an entry:
  a gene with no GWAS trait draws no pill.
- `definition` holds the STRIVE-2 text now hard-coded at
  `phenogram.html:255-301` (BG-PVS, WMH, lacunes, CMB); `strive: true` adds the
  citation link to that trait's tooltip.
- **Colour is a family cue, identity is text.** Each trait renders as a _pill_ —
  the trait label on the family tint with a 1 px family-hue border — not a
  coloured circle. This is what makes the figure legible in print and to
  colour-blind readers, where the current 14-hue circles are not, and it is what
  the data-viz method requires once a categorical set exceeds what any palette
  can keep pairwise distinct (see below). Family hues are the seven validated
  categorical slots of the dataviz reference palette minus yellow (the one below
  2.2:1 on white), in the order above — chosen by enumerating all 720 legend
  orders with `validate_palette.js --mode light --surface
  #ffffff`: 4 pass
  both adjacent gates; this one has worst adjacent CVD ΔE 9.2 (deutan, ≥ 8) and
  worst adjacent normal-vision ΔE 15.6 (≥ 15). Aqua (2.82:1) and magenta
  (2.69:1) sit below 3:1 on white, which the pill text relieves. Under
  `--pairs all` no 7-hue set passes (worst CVD 3.2, normal 7.1) — the reason hue
  is never the sole identity channel here. Tints are OKLCH L 0.94, C 0.045 on
  each family hue; every tint reads ≥ 14:1 against the plate ink.
- `stains` fixes the band greys for both renderers; `layout` fixes the geometry
  constants so both renderers scale to their own canvas.
- **`tests/phenogram_encoding_test.ts` is the guardrail** (CI, pure Deno): trait
  keys equal the `GWAS_TRAIT_CHOICES` values minus `SHOW_ALL` and `NONE_FOUND`
  in both directions; every non-sentinel `gwasTrait` in the committed data has
  an entry; every trait's family exists; families are exactly the seven above in
  this order; hues and tints are valid hex, hues pairwise distinct with OKLCH L
  in 0.43–0.77 and adjacent OKLab ΔE×100 ≥ 15 (the two gates that need no CVD
  simulation; the CVD result is recorded above, design-time); `stains` covers
  the eight UCSC stain values. A new GWAS trait in the data fails this test
  until it has an entry — the point.

## Part 1 — in-app island

- **`lib/phenogram.ts`** — pure, DOM-free layout over `genes` from
  `lib/data.ts`, the cytoband table and the encoding. Returns:
  - `rows`: chromosomes that carry at least one placed gene (today 19, now
    including 13), in `CHROMOSOMES` order, split into two rows after
    `layout.rowSplitAfter`; each chromosome scaled so chr1 is `rowHeight` tall,
    drawn as two rounded arms meeting at the centromere with band rects filled
    from `stains`; column pitch = `chromosomeWidth` + gap + `labelColumn`.
  - `blocks`: one per placed gene — marker y at the band midpoint; block = gene
    symbol line (the evidence glyphs follow the symbol at its renderer-measured
    width) + one pill per `gwasTrait` on its own line, so block heights follow
    from counts alone (glyphs: triangle when `evidenceFromOtherOmicsStudies` has
    a non-sentinel value, square when `linkToMonogenicDisease` does, star when
    `mendelianRandomization ===
    "Yes"`); resolved per chromosome by sorting
    on marker y, sweeping down to enforce `blockGap`, sweeping back up if the
    last block overflows the row — the linear twin of the timeline's radial
    nudge; leader = one straight segment from the chromosome's right edge at the
    marker to the block's left-middle. Marker ticks are ink-coloured; colour
    lives only in the pills.
  - `unplaced`: genes whose band did not resolve, so a regenerated table can
    never crash the page; the island lists them in a visible note.
  - `legend`: families with their traits in encoding order, plus the evidence
    key.
- **`islands/Phenogram.tsx`** — `<figure class="phenogram">` on a light plate
  (both themes; hue encodes meaning, same rule as the timeline — reuse
  `--svd-figure-ink`; `.phenogram-scroll` / `.phenogram-canvas` mirror the
  timeline's `.timeline-scroll` / `.timeline-figure` rather than generalizing
  them, since the timeline's styling was still moving on its own branch, and the
  canvas is painted with the fixed `--svd-figure-plate` token). Beside the
  plate, as the timeline's legend sits, the HTML legend; inside the card a
  `.phenogram-scroll` (`overflow-x: auto`, so `e2e/tests/runtime.spec.ts` stays
  green at 390 px) holding a `.phenogram-canvas` box with `aspect-ratio` = the
  viewBox and a min-width. The `<svg viewBox aria-hidden="true">` draws
  chromosomes, bands, leaders, labels and pills — decoration. Over it,
  `<ul class="phenogram-genes">` with one absolutely positioned `<li>` per block
  (percent coordinates of the viewBox, so the overlay scales with the SVG), each
  wrapping a `<Tooltip content={phenogramTooltip(gene)}>` whose child is a
  `.visually-hidden` name ("LAMB1, 7q31.1; GWAS: none found; other omics: none;
  monogenic: none; MR: no"). `Tooltip` already renders a real
  `<button popovertarget>` (`components/Tooltip.tsx:158-190`), so hover, Tab,
  Enter, Escape and the link inside the panel work exactly as in the tables with
  no new tooltip code (the timeline needed a drawer because its interactive
  marks are SVG groups; here the marks are HTML buttons, so the native popover
  path is enough); the island only styles `.phenogram-genes
  .tooltip-box` to
  fill its `<li>` and shows a `:focus-visible` ring on the label block.
  Sixty-three buttons in chromosome order are the screen-reader reading of the
  figure; `.visually-hidden a` stays at zero because the link is in the popover,
  not in the hidden span. Legend phenotype pills are `Tooltip`s too (name,
  STRIVE-2 definition, citation link), which keeps today's "hover a phenotype
  for its definition" affordance and makes the 15-item text key visible legend
  text instead of a hidden list. Renders on the server as well — nothing touches
  `window`.
- **`lib/tooltips.ts`** — `phenogramTooltip(gene)`: rows Location, GWAS
  phenotypes (labels from the encoding), Other omics, Monogenic disease (OMIM
  numbers resolved through `omimByNumber` when present), Mendelian
  randomization; link "View on NCBI Gene" via `geneInfoByName` when a uid
  exists. Unit test alongside `geneTooltip` in `tests/tooltips_test.ts`.
- **`routes/phenogram.tsx`** — `Page` + one `TipBox` ("Hover over or focus a
  gene to see its location, phenotypes and evidence; hover a phenotype in the
  key for its STRIVE-2 definition.") + island, instead of `EmbedPage`.
- **`assets/app.css`** — `.phenogram-*` rules on semantic tokens only (styles
  contract); trait colours and stains are inline SVG `fill`s from the encoding,
  like the map markers.
- **Deletions** — `static/phenogram.html`, `static/images/phenogram.webp`, the
  `static/phenogram.html` entry in `deno.json` `exclude`. The timeline is
  already drawn in-app (`islands/TrialsTimeline.tsx`, 2026-08-29), so the
  phenogram was the last embed and these go with it: `components/EmbedPage.tsx`,
  `islands/EmbedFrame.tsx`, `THEME_MESSAGE` in `lib/theme.ts`, the
  `.embed-frame*` rules, and the iframe branch of `e2e/tests/theme.spec.ts`
  (this supersedes the timeline spec's "stay for the phenogram" lines 127–130
  and 137). Nothing needs `allow-same-origin` any more.
- **Tests**
  - `tests/cytobands_test.ts`: 24 chromosomes in `CHROMOSOMES` order; bands
    sorted, contiguous, inside the length; one centromere pair each; every
    `chromosomalLocation` in the committed table resolves.
  - `tests/phenogram_layout_test.ts`: 63 blocks, `unplaced` empty, 19
    chromosomes drawn including "13", chromosome heights proportional to length,
    every marker inside its chromosome at its band midpoint, no two blocks on a
    chromosome closer than `blockGap`, no block outside its row, pill/glyph
    derivation for JAK1 (PSMD; triangle, square), PCSK9 (no pill; triangle,
    square, star), LAMB1 (nothing), TLR1 (triangle, star), CENPF (WM-PVS,
    HIP-PVS, PSMD; triangle, square); legend lists 7 families / 14 traits in
    encoding order.
  - `tests/phenogram_encoding_test.ts` as above.
  - e2e `e2e/tests/phenogram.spec.ts`, replacing the phenogram tests of
    `e2e/tests/embeds.spec.ts` (`:9-133`, `:305-312`): 63 gene buttons with
    accessible names; chromosome label "13" in the SVG; Tab to the first gene →
    Enter → popover `.is-placed` containing "View on NCBI Gene"; hover the "WMH"
    legend pill → its STRIVE-2 definition; `.visually-hidden a` = 0; theme
    toggle changes the page background but not the plate; one `.tip-box`.
  - Python: `tests/scripts/test_fetch_cytobands.py` — parser and filter on a
    fixture, chromosome order.

## Part 2 — matplotlib paper figure

- `scripts/phenogram_figure.py` — same docstring/argparse style as
  `scripts/validate_pipeline.py`; plain matplotlib (already a base dependency;
  pyideogram would replace only the band loop, at LGPL cost, so it is not
  added). Reads `data/table1.json`, `data/cytobands_hg38.json` and the encoding
  — no CSV step. Layout functions mirror `lib/phenogram.ts` names
  (`chromosome_rows`, `place_gene`, `label_blocks`, `resolve_collisions`) so the
  two read side by side.
  - Arms as `FancyBboxPatch(boxstyle="round")` with band `Rectangle`s clipped to
    the arm path (`set_clip_path`); markers and leaders as `Line2D`; labels as
    `Text`; pills as
    `Text(bbox=dict(boxstyle="round,pad=0.25",
    fc=tint, ec=hue))` — measured
    by the real font renderer, so collisions are resolved on measured extents
    after `fig.canvas.draw()`; evidence glyphs as markers `^`, `s`, `*`.
  - Legend: family swatches + trait pills drawn as an inset panel (matching the
    app's legend), evidence key via `ax.legend` `Line2D` handles.
  - Options: `--out figures/`, `--format svg pdf png` (default all),
    `--dpi 300`, `--font PATH.ttf` (journals want Arial/Helvetica; IBM Plex
    ships here only as woff2). rcParams `svg.fonttype = "none"`,
    `pdf.fonttype = 42`.
- Packaging: the `figure` dependency group and gitignored `figures/` from the
  timeline spec; `deno task figure` runs both scripts.
- Tests: `tests/scripts/test_phenogram_figure.py` — layout functions against the
  committed table (63 blocks, same blocks-per-chromosome as the Deno test lists,
  `unplaced` empty) and a render smoke test to `tmp_path` asserting the SVG
  carries 63 gene `gid`s and both legend panels. `ruff` and `ty` clean.

## Decisions recorded

1. In-app island, no charting library; matplotlib print twin kept (mirrors the
   timeline — strike Part 2 if the manuscript does not need it).
2. Gene-level tooltips plus legend definitions, replacing phenotype-only hover.
3. Chromosomes drawn: only those carrying a gene (as today, now 19).
4. Placement at band midpoint; bp enrichment deferred.
5. The timeline island landed first (same day); this change removes the embed
   scaffolding it left in place for the phenogram.
6. Trait identity as text pills tinted by family (7 validated hues), not 14
   colour-only circles.
